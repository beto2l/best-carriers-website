# Best Carriers website agent guide

This repository is the source of LuxWrap-managed pages inside the existing WordPress site at `best-carriers.com`. WordPress and Divi continue to own every route not declared in `lw-release.json`.

## Read before editing

1. Read `README.md`, `content/site.json`, `content/services.json` and `lw-release.json`.
2. Treat `content/` and `src/` as source. Files under `pages/` and `lw-release.json` are generated by `npm run build`.
3. Keep the LuxWrap release at contract version 4, runtime `static` and scope `pages`.
4. Never change an existing page `id`; WordPress uses it to preserve the native Page ID, menus, taxonomies and SEO metadata.

## Required workflow

1. Edit the canonical content or source assets.
2. Increase the version in `package.json` for every release whose bytes change.
3. Run `npm test`.
4. Review `git diff` and commit only intended files.
5. Push `main`.
6. In WordPress, open `OPIN X > LuxWrap Studio`, review the exact commit and publish it.
7. Verify both public routes, the native WordPress Pages, the CDN image and cache behavior.

## Safety and content rules

- Do not add secrets, WordPress credentials, CDN tokens or API keys.
- Do not invent regulatory requirements. Until verified requirements are supplied, retain the explicit evaluation placeholder.
- Preserve the WhatsApp destination and approved message unless the owner requests a change.
- Use OPIN X CDN URLs only for images already uploaded server-side through the site's authorized CDN client.
- Keep service content in both Spanish and English.
- Maintain semantic HTML, keyboard support, visible focus, reduced-motion support and a no-JavaScript fallback.
- Browser JavaScript may load only checksummed, public release files or approved public OPIN X endpoints.
- Do not send contact, sale or advertising events until an approved server-side bridge is configured and tested.
